# 局所探索の実装と実験の読み方

提出用コードは `lab-competition-2026/` にあります。配布元の `upstream/` は編集せず、コミットも作成していません。01〜04では個体数200・世代数100を含む元の定数をそのままにしていましたが、05で既定値を個体20・世代20・候補40地点・世代表示なしに更新しました（下の「05で変えたところ」）。評価式・重み・交叉・突然変異は配布コードのままです。

## 探索するコース

初期個体すべてと、交叉・突然変異後の子個体すべてに局所探索を呼び出します。エリートとして引き継ぐ個体は再探索しません。子を2個作り、個体数の都合で片方だけを採用する場合も、両方に局所探索を適用します。

地点数が6～12のコースについて、追加・削除・置換・区間反転（2-opt）・1地点の移動（Or-opt）を全列挙します。各回で最も評価値Eが下がる手を1つ採用し、改善がなくなるまで繰り返します。同点の手には移動せず、同じ最良値の候補が複数ある場合は列挙順で最初のものを選びます。探索回数の打切りや近傍の間引きはありません。

交叉・突然変異で地点数が範囲外になった子は、配布コードと同じ無効解の罰点で扱います。地点数を修復すると別の変更が混ざるため、今回は修復しません。地点数が有効で経路が到達不能な場合は、探索を行い、有限の評価値になる近傍があれば採用します。

## 染色体への書き戻し

配布コードの `decode()` は、選択地点を候補番号順に並べ、順序パートの値を小さい順に読んで巡回順を決めます。したがって、`chrom[N+k]` に入れるのは「候補番号順でk番目に選択された地点の巡回順位」です。巡回順に地点番号をそのまま格納すると元のコースには戻りません。

使用する順位は0～n−1、残りの添字 `N+n` から `N+MAX_CONTROLS-1` にはn～11を入れます。順序パートを0～11の順列に保つことで、配布コードの順序交叉も引き続き使えます。

## 評価の一致

近傍は `evaluate_course()` で評価します。染色体のデコードと評価結果の構造体作成を省き、候補番号で距離・登り・密集の罰点の表を参照します。距離と登りは正門から巡回順に、密集の罰点は元の二重ループと同じペア順で足します。区間反転でも登りは方向に依存するため、距離の差分だけで評価しません。

03-speedupで、道路ノードをID順の連番に変え、Dijkstraの隣接リスト・距離・親を配列にしました。親は距離が厳密に短いときだけ更新し、同距離なら元のID順で処理します。登りは親から子への最初の辺を使い、終点から親へたどる加算順も保ちます。`PathCache` は候補と正門の組み合わせだけを保存し、道路上の任意の終点を調べる場合は `Graph::dijkstra_from()` を使います。

`EvaluationTables` を事前計算で一度作り、GAの通常評価と局所探索で共有します。表を渡さない `evaluate()` と元の `f_dist()` は比較用の計算を残しています。近傍の作業用配列は使い回しますが、近傍の列挙順・最良手の受理・乱数消費・重み・無効解の罰点は変えていません。測定と厳密比較の結果は [03-speedupの報告](03-speedup.md) に記録しました。

`lab-competition-2026/test.bat` で検証できます。6～12地点のランダムコース700件と、局所探索で得た10コースおよびその全近傍を含む19,560件で、往復変換・順序パートの順列・元の評価値との完全一致を確認しました。探索前後の非悪化、終了後の全近傍に改善がないこと、地点数違反と到達不能時の扱いも検証対象です。

## 実験の再実行

プロジェクト直下から実行します。同じ実験名は上書きせず、新しい名前を指定してください。

```powershell
python tools/run_experiments.py --label example --seeds 1..10 --pop 20 --gen 20 --note "個体20、世代20で比較"
```

`--seeds 1 2 3` と `--seeds 1,2,3` も使えます。個体数・世代数を省略すると `const.h` の値になります。プログラム単体の引数は `orienteering.exe 種 個体数 世代数` です。局所探索を無効にする場合は `USE_LOCAL_SEARCH` をfalseにしてビルドし直します。

04では実行時の比較用引数を追加しました。どれも省略時は無効なので、上記の全近傍探索が既定のままです。ランナーにも同名の引数を渡せます。

| 引数 | 有効にしたときの動作 |
|---|---|
| `--dedupe` | 同じ巡回順の探索結果を1回のGA実行内で共有する。入力と探索終了後の巡回順をキーとして記憶し、染色体への書き戻しは通常と同じ形にそろえる |
| `--first-improvement` | 元と同じ固定順で近傍を調べ、最初の改善手を採用する。改善がなくなるまで続ける |
| `--candidate-k K` | 挿入・置換位置の前後それぞれから、道のりが近い未選択K地点を取り、その和集合だけを調べる。0は全候補。正門を含み、同距離は候補番号順 |
| `--quiet` | 世代ごとの行を省く。最後のまとめと世代履歴CSVは残す |

候補絞り込みでは、置換する地点を外した後の前後を使います。ただし置換前に選択済みの地点は候補から除きます。近さは各端点から候補への距離で決め、候補の走査自体は従来の候補番号順を維持します。削除・区間反転・1地点移動は絞りません。終了時に改善手がないと保証できる範囲は、許可した近傍だけになります。

```powershell
python tools/run_experiments.py --label example-c40 --pop 20 --gen 20 --candidate-k 40 --note "候補を40地点ずつに絞る"
```

既存の `test.bat` は全変更OFFの局所探索を検証します。追加の `test_efficiency.bat` は変更ONでの非悪化、許可した近傍での局所最適性、乱数状態と重複スキップの一致を調べます。実験結果の再現確認は `python tools/verify_efficiency.py` です。比較表と推奨は [04の報告](04-efficiency.md) にまとめています。

## 05で変えたところ

`const.h` の既定値を個体20・世代20・候補40地点・世代表示なしに更新しました。種は42のままです。引数を1つも渡さずに `orienteering.exe 種` と実行すると、この設定で動きます。

| 引数 | 動作 |
|---|---|
| `--verbose` | 世代ごとの行を表示に戻す（既定は表示しない） |
| `--candidate-k 0` | 候補の絞り込みをやめて全候補を調べる（既定は40地点） |
| `--init random` | 初期個体を配布コードと同じでたらめな選び方にする（既定） |
| `--init greedy-all` | 初期個体をすべて貪欲構築にする |
| `--init greedy-half` | 前半の個体だけ貪欲構築、後半はランダムのまま |
| `--restarts R` | 種 s, s+1, …, s+R−1 でGAをR回走らせ、最良の解を採る（既定は1）。読み込みと事前計算は1回だけで、最短経路の表は全回で共有する。R=1の出力は引数なしと1ビットも変わらない |

貪欲構築は、正門から始めて「選択済みのどれとも150m以上離れている」「入れたあとの推定時間が60分を超えない」地点のうち、道のりの増え方が小さい上位3件から乱数で1つ選び、増え方が最小の位置に差し込む操作を、8地点になるか候補が尽きるまで繰り返します。そのあとは従来どおり局所探索をかけます。測定では最終的なEが悪化したため既定にはしていません（[05の報告](05-init-and-overhead.md)）。

読み込みと事前計算も作り直しましたが、探索の手順・乱数の使い方・評価規則は変えていないので、同じ種なら同じ解になります。確認は `python tools/verify_overhead.py` です。変更前のソース一式は `docs/experiments/05-validation/before-source/` に置いてあります。

標準出力には固定費の内訳（地点CSV秒・ノードCSV秒・エッジCSV秒・正門CSV秒・グラフ構築秒・正門探索秒・最短経路秒・表作成秒）と、世代交代を始める前の最良値（初期集団E）も出しています。

Eの平均・標準偏差・最小・最大は指定どおり標準出力から集計しています。ただし配布コードの表示は小数4桁なので、局所探索で非常に小さいEが得られると差が丸められます。最良値への到達数は小数6桁のJSON値を使い、差が厳密に0.000001未満かを十進数で比較します。これも丸め前の完全な一致を示すものではありません。生データには両方の値、各目的関数、コース、標準出力、ソースのSHA-256を保存します。

時間も配布コードに合わせて小数2桁の表示値を集計します。GA時間には初期個体生成と局所探索を含み、総時間には読み込み・経路の事前計算・結果出力を含みます。30秒を超えた種は警告を記録したうえで測定を継続します。最初の試行では30秒で打ち切りましたが、これは探索条件を緩めず全種を測定する方針に変更しました。

## 07で追加したところ

独立やり直し `--restarts R` を追加しました。既定値（`const.h` の `DEFAULT_RESTARTS`）は1で、従来の動きと同じです。ランナーにも `--restarts` を渡せます。

```powershell
python tools/run_stability.py --run      # データ5種 × 設定5通りをまとめて測る
python tools/run_stability.py --report   # 記録済みJSONから比較表を組み立てる
python analysis/reference_search.py --all --restarts 1000 --chunks 10 --report
```

標準出力に `再スタート回数` と `再スタートE`（各回の最良評価値）を足しています。`GA詳細秒`・`初期個体秒`・`世代ループ秒` は全回の合計、`best_course.json` と世代履歴は採用した回のものです。測定結果と推奨は [07の報告](07-stability.md)、別実装で求めた到達目標は [参照解の報告](analysis/reference_search.md) にあります。
