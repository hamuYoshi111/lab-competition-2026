# 読み込みと事前計算を削って総時間を1割強縮めた。賢い初期解は逆効果だった

既定値を「個体20・世代20・候補40地点・世代表示なし・種42」に更新した。この既定のまま、CSVの読み込みと最短経路の事前計算を作り直し、10種の平均総時間を0.122秒から0.107秒へ短縮した。10種すべてで最終コースと全世代の履歴が変更前と1ビットも変わらないことを確認している。

一方、目標（8地点・60分・登り50m以内・地点どうし150m以上）に近いコースを最初から組み立てる「賢い初期解」は、初期集団の評価値を0.042から0.015へ良くしたが、最終的な評価値は0.00058から0.00183へ悪化した。時間の短縮も0.004秒にとどまるため採用しない。

**推奨する最終候補**: 個体20・世代20・候補40地点・世代表示なし・初期解はランダム（今の既定値そのまま）。E平均0.00058、標準偏差0.00049、総時間0.107秒。

## 1. 既定値の更新

`const.h` を次のように変えた。実行時引数での上書きはすべて残してある。

| 項目 | 変更前 | 変更後 | 理由 |
|---|---:|---:|---|
| 個体数 `POP_SIZE` | 200 | 20 | 04の比較で質と時間の釣り合いが最良だった |
| 世代数 `N_GEN` | 100 | 20 | 同上 |
| 候補の絞り込み `DEFAULT_CANDIDATE_K` | なし（全候補） | 40 | 04で解を変えずに約30%短縮できた |
| 世代ごとの表示 `DEFAULT_QUIET` | 表示する | 表示しない | 画面出力は採点に関係しない |
| 乱数の種 `RANDOM_SEED` | 42 | 42（変更なし） | 同じ種で同じ結果を保つため |

既定が「表示しない」になったので、表示に戻すための `--verbose` を足した。`--candidate-k 0` を指定すれば従来どおり全候補を調べる。

`05-defaults`（引数なしで実行）は、04で推奨した `04c-cand40` と10種すべてで最終コースのJSONと世代ごとの履歴が完全に一致した。E平均0.00058、標準偏差0.000492、総時間0.122秒も一致している。既定値を書き換えただけで探索は変えていないことの確認である。

### 何を変えたか

**CSVの読み込み**（8.8ms → 2.4ms）。変更前は1行ずつ読み、カンマで区切るたびに文字列を作り直し、`std::stod` で数値にしていた。変更後はファイルを丸ごと1回で読み、中身は切り出さずに「どこからどこまで」を指すだけにし、数値化には `std::from_chars` を使う。`std::from_chars` は「いちばん近い double に丸める」規則が `stod` と同じなので、読み取れる値は1ビットも変わらない。

**最短経路**（17.1ms → 13.5ms）。3つ変えた。(a) 113の候補が指す道路ノードは、重なりを除くと91か所しかない。同じ場所から2度探索しても結果は同じなので、1度だけ計算して行を写す（114回 → 92回）。(b) 探索のたびに2267要素の作業用配列を作り直して0で埋めていたのをやめ、一度確保したものを使い回す。「今回の探索で触ったか」は世代番号で見分ける。(c) 優先度つきキューを、取り出しが1回の下りで済む形に書き直した。

(c) が安全な理由は、キューに入る「(距離, ノード番号)」の組が2度と同じ値にならないからである。同じノードを積み直すのは距離が厳密に短くなったときだけなので、同じ組は1度しか入らない。したがって取り出す順は中の並べ方に関係なく一意に決まり、標準ライブラリのキューと同じ順序になる。

**やってみて効かなかったこと**: 隣接リストを1本の配列にまとめる、作業用データを1ノードぶんずつ隣り合わせに置く、といった置き方の工夫は、単独ではほとんど差が出なかった。残る13.5ミリ秒は「2267ノードを92回たどる」計算そのものの費用で、ここから先を削るには取り出し順を変える必要がある。取り出し順を変えると同じ距離の経路が別のものに変わり、累積登りの値が変わりうるため、今回は手を付けていない。

### 結果が変わっていないことの確認

`python tools/verify_overhead.py` で2通り確かめた。どちらも一致した。

1. 丸める前の値を16進表記で全部出す `speedup_test` を、変更前のソース一式（`docs/experiments/05-validation/before-source/`）と現在のソースの両方でビルドし、出力を全文照合した。正門から全到達ノードへの距離と登り、人工グラフ、700コースの評価値、種1〜3の20個体20世代を含む。
2. 実際の `orienteering.exe` を両方のソースでビルドし、既定設定で種1〜3を実行して `best_course.json` と `fitness_history.csv` をバイト単位で照合した。

さらに `05-overhead`（10種）の最終コースと世代履歴は `05-defaults` と全10種で一致した。

## 3. 賢い初期解

### やったこと

配布コードの初期個体は「6〜12地点をでたらめに選び、でたらめな順で回る」ので、目標からかけ離れたところから始まる。そこで次の手順で最初から目標に近いコースを組み立て、`--init greedy-all`（全個体）と `--init greedy-half`（前半の個体だけ）で切り替えられるようにした。

1. 正門だけの空のコースから始める
2. まだ選んでいない地点のうち、選択済みのどれとも150m以上離れていて、入れたあとの推定時間が60分を超えないものを候補にする
3. 候補ごとに「どこに差し込むと道のりの増え方がいちばん小さいか」を調べる
4. 増え方の小さい順に並べ、上位3件から乱数で1つ選んで差し込む
5. 8地点になるか、候補が尽きたら終了

4で必ず1位を選ぶと全個体が同じコースになるため、少しだけ運を混ぜている。組み立てたあとは従来どおり局所探索をかける。

### なぜ効いた・効かなかったか

**固定費の削減が効いた理由**。総時間の2割強が「ファイルを読む」「最短経路の表を作る」で、探索の中身とは無関係に毎回かかる。CSVは1行につき5個の文字列を作って捨てていたので、作らずに済ませるだけで4分の1になった。最短経路は、113の候補が指す道路ノードが91か所しかないという入力データの性質を使って、探索回数を114回から92回に減らせた。どれも計算の中身を変えていないので、答えは1ビットも変わらない。

**賢い初期解が効かなかった理由**。初期集団の評価値は狙いどおり良くなった（0.042 → 0.015）。それでも最終結果が悪いのは、良い初期解が「どれも似たコース」になり、集団の散らばりが失われるからだと考えている。証拠として、最後に改善があった世代は、ランダムでは平均13.1世代目なのに対し、全個体を貪欲にすると10.1世代目で止まる。早く行き詰まって、そこから抜け出せていない。半数だけ貪欲にすると13.0世代目まで改善が続き、悪化も小さくなる（0.00183 → 0.00153）ことも、原因が散らばりの不足であることを支持する。なお、これは世代ごとの最良値から読み取った推測で、集団の中に何種類のコースがあるかを数えたわけではない。

**もう1つの弱点**。60分の枠に入る未選択地点が先に尽きるため、貪欲構築が8地点そろうのは20回中13回だけだった。残りは6〜7地点で終わり、地点数の罰点（重み0.5）を抱えたまま局所探索に渡される。ただし最終結果はどの設定でも8地点になっているので、地点数そのものは局所探索が直している。

**教科書との違い**。「良い初期解から始めれば少ない世代で済む」は一般には正しいが、遺伝的アルゴリズムは集団の違いを材料に新しい解を作るため、初期解を良くしすぎると材料が足りなくなる。04の「最初の改善手を採用する」と並んで、発表で使える「理屈どおりにいかない例」である。

**小さい設定でも同じ**。10×20・10×10でも順位は変わらず、ランダムが最良だった。10×20の貪欲半数（0.00134）はランダム（0.00119）に近いが上回ってはいない。

## 4. 推奨

**個体20・世代20・候補40地点・世代表示なし・初期解はランダム・種42**。つまり現在の `const.h` の既定値そのままで、追加の実行時引数は不要である。

| 指標 | 値 |
|---|---:|
| E平均 | 0.00058 |
| E標準偏差 | 0.00049 |
| 総時間 | 0.107秒 |

理由は3つある。第一に、04の判断どおり採点で効くのは時間と安定さで、Eは0.01を大きく下回っていれば参加者間の正規化後にほとんど差が出ない。第二に、貪欲初期解はEの平均を3.2倍、標準偏差を4.6倍に悪化させる一方、短縮できる時間は0.004秒（4%）しかない。第三に、固定費の削減は答えを変えずに0.013〜0.015秒（11〜12%）を削れたので、無条件に取り入れてよい。同じビルドを並べて測った内訳では11%（122.4→109.1ミリ秒）、10種の実験どうしの比較では12%（0.122→0.107秒）だった。

さらに時間を削る必要が出た場合の順序は、(1) 候補の絞り込みをK=20にする（04の測定で総0.091秒、E平均0.00082）、(2) 個体10・世代20にする（総0.062秒、E平均0.00119）。どちらもEは0.01より十分小さいままである。逆に質を上げる余裕ができたら個体30・世代30（04で総0.236秒、E平均0.00031）に戻せる。

参加者間の正規化に必要な他者の値がないため、合成得点を最大にする設定までは断定できない。また、別のデータでも同じようにEが小さくなる保証はないので、質を大きく捨てる設定（5×5など）は選ばない方針を続ける。
