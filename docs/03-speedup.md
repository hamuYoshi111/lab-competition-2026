# 探索結果を保ち、平均総時間を1.601秒から0.168秒へ短縮

個体20・世代20、種1〜10の平均総時間は約9.53倍速くなりました。過去の02-pop20-gen20と全10種の出力コースが一致し、種1〜3では今回保存した変更前の実行ファイルともJSON全体がバイト単位で一致しています。0.1秒未満は未達です。

測定日は2026年9月18日。Windows、MSVC Build Tools 2022、既存の `/O2` でビルドし、標準出力を捕捉して測りました。今回のGA実験はすべて個体20・世代20です。

## 時間の大半を占める世代ループが約10倍に短縮

種1の単発比較。前後とも同じ場所に時計を置き、小数6桁で記録しました。

| 区分 | 変更前（秒） | 変更後（秒） |
|---|---:|---:|
| CSV読み込み | 0.008496 | 0.008889 |
| 事前計算 | 0.177346 | 0.018399 |
| 初期個体生成＋局所探索・初期評価 | 0.099250 | 0.009453 |
| 世代ループ | 1.352535 | 0.130414 |

事前計算にはグラフ構築、正門の最近傍検索、最短経路の計算、変更後の評価用表の作成を含みます。世代ループには世代ごとの表示も含めました。4区分の外に引数処理、最終評価、結果出力などがあり、総時間の表示は変更前1.64秒、変更後0.17秒です。単発の内訳には測定の揺れがあるため、集計値とは区別してください。

出典は [変更前の種1ログ](experiments/03-validation/before-1.log) と [変更後の種1ログ](experiments/03-validation/after-1.log)。変更前ソースには時間計測だけを追加してから保存しました。

丸めによって差が隠れないように、変更前後のソースで同じ検証プログラムをビルドし、浮動小数点の値を16進表記で出力して比較しました。全候補・正門から全到達ノードへの距離と登り、700コースの評価、種1〜3の最終評価・距離・登り・コース・全世代の評価値履歴に差はありません。同距離経路や並行辺、ゼロ距離の辺を持つ人工グラフも検証しています。孤立点と未知の始点に加え、加算順で丸めが変わる登りも比較対象です。

既存の `test.bat` も変更せず実行し、19,560コースの往復変換・評価一致・局所最適性の検証に合格しました。[テストログ](experiments/03-validation/test.log) を保存しています。

ビルドに伴い提出用フォルダーの `.obj`、`orienteering.exe`、`local_search_test.exe` を更新し、`output/best_course.json` と `output/fitness_history.csv` は最後の一致確認で使った種3の結果になっています。

`csv_loader.cpp` は約0.009秒で影響が小さいため変更しませんでした。`upstream/` と入力CSV、`const.h` の個体200・世代100を含む既定値は維持しています。重みや乱数、交叉・突然変異、近傍の列挙順と受理規則も元のままです。既存テストとビルド設定、実験スクリプトは変更せず、コミットも作成していません。

0.1秒を切るために探索を減らす変更は加えていません。計算順の変更による丸めの差を避け、距離・登り・密集の罰点は元の順に集計します。互換用の `evaluate()` と `f_dist()` には従来の計算を残しました。通常のGAは事前計算した表を使う構成です。`PathCache::get()` の保存範囲は要求どおり候補と正門の間だけで、任意の道路ノードへの問い合わせには公開の `Graph::dijkstra_from()` を使います。
