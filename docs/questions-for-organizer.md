# 主催者への確認事項 (Slack #case_study 投稿用の下書き)

投稿前にユーザーが文面を確認・修正すること。回答が来たら本ファイルに追記し、判断ノートにも反映する。

## 1. f_dist の正規化 (課題文と配布コードの違い)

課題文の式 (2) では f_dist を 2/(n(n+1)) で割っていますが、配布コード evaluate.cpp では地点ペア数 n(n−1)/2 で割っています (コメントにも「nC2 で正規化」とあります)。採点時の評価値はどちらで計算されますか。配布コードの計算に合わせて実装してよいでしょうか。

## 2. 推定時間の式 (登り時間の単位)

課題文の式 (5) は t = distance/WALK_SPEED × 60 + gain/CLIMB_SPEED で、登りの項に ×60 がありません。配布コードでは両方の項に ×60 を掛けて分に揃えています。配布コードの計算 (両方 ×60) が正でよいでしょうか。

## 3. 処理時間の測り方

最優秀賞の T(Pk) は、(a) プログラム全体の実行時間 (CSV 読み込みや最短経路の事前計算を含む) と、(b) プログラムが表示する GA 部分の実行時間のどちらでしょうか。また、10 回実行は同一マシンで逐次実行という理解でよいでしょうか。

## 4. 乱数の種の固定

10 回実行のばらつき (SD) を評価するとのことですが、プログラム内で乱数の種を固定して毎回同じ結果を出す実装は許容されますか。それとも実行ごとに異なる種 (時刻など) を使うことが求められますか。

## 5. 評価値の取り方

各実行の「出力解の評価値」は、best_course.json の fitness をそのまま使いますか、それとも主催者側で controls / course_nodes から再計算しますか (再計算の場合、上記 1・2 の式がどちらになるかが重要になります)。
