# orienteering-competition2026

大学の正門をスタート・ゴールとして、地図上の候補地点から 8 か所を選び、
回る順番も決めて 1 つのオリエンテーリングコースを作るプログラムです。
「地点数が 8 に近い」「地点どうしが 150 m 以上離れている」「1 周が 60 分に近い」
「登りの合計が 50 m 以内」という 4 つの希望を重み付きで足した値 E を、できるだけ小さくします
(E は小さいほど良い)。配布された遺伝的アルゴリズム (GA) のプログラムを土台に、
一つひとつの解を作り直して改善する「局所探索」を組み合わせました。
配布プログラムの E が平均 1.47 だったのに対し、このプログラムは平均 0.00056 で、
実行時間は 0.24 秒から 0.16 秒に短くなっています。

## 手法の要点

**1. 遺伝的アルゴリズムに局所探索を足した (memetic algorithm)**
配布プログラムの GA は、コースを表す「染色体」を交叉・突然変異で混ぜて世代を進めます。
そこに、生まれた各コースを「これ以上良くならなくなるまで手直しする」処理を足しました。
手直しの種類は、地点の追加・削除・入れ替え、巡る区間の反転 (2-opt)、1 地点だけ別の位置に移す (Or-opt)
の 5 つで、いちばん E が下がる手を選んで繰り返します。
E は 1.47 から 0.00058 に下がりました。

**2. 手直しで試す地点を近い 40 か所に絞った**
地点を追加・交換するとき、候補 113 か所すべてを試す代わりに、
その位置の前後の地点から道のりが近い 40 か所ずつだけを試します。
得られる解は変わらないまま、探索時間が約 3 割減りました。

**3. 同じ計算を表に作り置きした**
地点どうしの最短経路・距離・登り・「近すぎる罰点」を最初に一度だけ計算して表に入れ、
探索中はその表を引くだけにしました。道路ノードの番号も連番に付け替えて配列で扱います。
答えを変えずに、全体で 1.60 秒 → 0.17 秒になりました。

**4. 1 回の探索を小さくして、3 回やり直す**
個体数を 20 から 10 に減らし、その代わり同じ探索を種を変えて 3 回走らせ、いちばん良い解を採ります。
候補地点が偏ったデータでは「1 回の探索がどの行き止まりに落ちるか」が運で決まるため、
1 回を強くするより回数を増やす方が効きました。最悪の回の E が 0.207 から 0.033 に下がっています。
入力の読み込みと表の作り置きは 3 回で共有するので、3 回起動するより 1 割ほど速く済みます。

**5. 乱数の種を 42 に固定した**
引数なしで実行すると必ず同じ答えが出ます。同じ環境で何度実行しても結果が変わらないので、
採点でばらつき (標準偏差) の項が 0 になります。

## ビルドと実行

### macOS / Linux

```bash
make          # ビルド
./orienteering
```

`make run` でビルドと実行をまとめて行えます。`make clean` で生成物を消します。
コンパイラは `g++ -std=c++17 -O2 -Wall -Wextra` です (g++ 13 と clang 18 で警告ゼロを確認)。

### Windows

```bat
build.bat
orienteering.exe
```

`build.bat` は Visual Studio Build Tools の `cl` を使います
(`cl /std:c++17 /O2 /EHsc /utf-8`、MSVC 19.44 で警告ゼロ)。

**実行する場所に注意**: プログラムは `input/landmarks.csv` のような相対パスでファイルを開きます。
`input` フォルダのある場所 (= このフォルダ) で実行してください。

### 実行時の引数

引数を 1 つも付けなければ、下の表の「省略時」の設定で動きます。提出時の設定はこれです。

```
orienteering 種 個体数 世代数 [オプション]
```

数字で書いた引数は前から順に 種・個体数・世代数、`--` で始まる引数はオプションとして読みます。
途中の数字を省くことはできませんが、オプションだけを付けることはできます
(例: `./orienteering --restarts 1`)。読めない引数があれば、入力を読み込む前に使い方を表示して終了します。

| 引数 | 省略時 | 意味 |
|---|---:|---|
| 種 (1 つめ) | 42 | 乱数の出発点。同じ種なら必ず同じ答えになる |
| 個体数 (2 つめ) | 10 | 1 回の探索が同時に持つコースの数 |
| 世代数 (3 つめ) | 20 | 交叉と突然変異を繰り返す回数 |
| `--restarts R` | 3 | 種を 1 ずつ増やしながら探索を R 回やり直し、いちばん良い解を採る |
| `--candidate-k K` | 40 | 手直しで試す地点を前後それぞれ近い K か所に絞る。`0` で全候補 |
| `--verbose` | 付けない | 世代ごとの経過を 1 行ずつ表示する (省略時は表示しない) |
| `--init 方法` | `random` | 初期コースの作り方。`random` / `greedy-all` / `greedy-half` |

実行例:

```bash
./orienteering                          # 提出時と同じ設定
./orienteering 7                        # 種だけ変える
./orienteering 42 20 20 --restarts 1 --verbose   # 経過を見ながら1回だけ探索する
```

比較実験用に `--dedupe` (同じコースの手直し結果を使い回す) と
`--first-improvement` (最初に見つけた改善手を採る) もありますが、省略時はどちらも無効です。

## 出力

実行すると `output/` フォルダが自動で作られ、2 つのファイルが書かれます。

- `output/best_course.json` … 最も良かったコース。地点数・総距離・累積登り・推定時間・E の値・
  4 つの目的関数の値と重み・選んだ地点の一覧 (名前・種別・緯度経度)・通った道路ノードの並び。
- `output/fitness_history.csv` … 世代ごとの最良 E。探索の進み方を折れ線にできます。

画面には、選んだ地点の巡回順・実行時間・E の値・各目的関数の値が表示されます。
そのあとに続く「〜秒」の行は、どこに時間がかかっているかを調べるための内訳です。

## 実験結果 (配布データ)

乱数の種を 10 通り変えて測った値です。E は小さいほど良く、秒は読み込みから書き出しまでの合計です。

| 段階 | 設定 | E 平均 | E 標準偏差 | E 最大 | 総秒 |
|---|---|---:|---:|---:|---:|
| 配布プログラムのまま | 個体 200・世代 100 | 1.468810 | 0.492798 | 2.644200 | 0.237 |
| 局所探索を足した | 個体 20・世代 20 | 0.000580 | 0.000492 | 0.001600 | 1.601 |
| 表の作り置きで速くした | 同上 | 0.000580 | 0.000492 | 0.001600 | 0.168 |
| 候補を 40 か所に絞った | 同上 | 0.000580 | 0.000492 | 0.001600 | 0.122 |
| **やり直し 3 回 (提出設定)** | **個体 10・世代 20・3 回** | **0.000557** | **0.000307** | **0.000998** | **0.157** |

最後の行だけは、やり直しで使う種が重ならないように 3 ずつ離した 10 個の種 (1, 4, …, 28) で測っています。
提出時に使われる種 42 での E は 0.000662 です。

配布データを加工した 7 種類のデータ (候補を半分に減らす、道を 1.5 倍に伸ばす、高低差を 3 倍にする など)
でも測りました。全 8 データで異常終了はなく、総時間はいちばん重いもので 0.169 秒です。
結果の表は [docs/08-final.md](docs/08-final.md) にあります。

## ファイル構成

```
.
├── const.h              定数と既定値 (課題の目標値・重み・GA の設定)
├── csv_loader.h/.cpp    入力 CSV の読み込み
├── graph.h/.cpp         道路グラフの構築と最短経路の事前計算
├── evaluate.h/.cpp      コースの評価 (4 つの目的関数と重み付き和)
├── ga.h/.cpp            GA 本体 (選択・交叉・突然変異) と局所探索
├── main.cpp             引数の解釈・全体の制御・結果の書き出し
├── Makefile             g++ 用のビルド設定 (make test で検証も実行できる)
├── build.bat            MSVC 用のビルド
├── test.bat             局所探索の検証 (下記)
├── test_efficiency.bat  速くした探索の検証 (下記)
├── tests/               上の 2 つのテスト本体 (make test からも走る)
├── input/               入力 CSV 4 本 (landmarks / nodes / edges / seimon)
├── output/              実行時に自動で作られる
├── docs/                手法を決めるまでの記録 (下記)
└── README.md
```

`input/` の 4 つの CSV は配布されたものです。
`landmarks.csv` がコントロールの候補地点、`nodes.csv` と `edges.csv` が道路網、
`seimon.csv` がスタート・ゴールになる正門の座標です。

## 検証方法

2 つの検証プログラムがあります。どちらも最後に `PASS:` と表示されれば成功です。

macOS / Linux:

```bash
make test    # 2 つをまとめてビルドして実行する
```

Windows:

```bat
test.bat             :: 局所探索そのものの検証
test_efficiency.bat  :: 速くしたあとの探索の検証
```

- `test.bat` (= `make test` の 1 つめ) … ランダムなコース 700 件と、局所探索で得た 10 コースおよび
  その全近傍を合わせた 19,560 件について、染色体への変換が元に戻ること・評価値が配布プログラムの
  計算と一致すること・探索を終えた時点でどの近傍にも改善手が無いことを確かめます。
  あわせて、探索が実際に使う「表を引く評価」と配布プログラムと同じ「参照の評価」が
  1 ビットも違わないことを 1,250 件で確かめ、到達できない点・同じ 2 点を結ぶ道が 2 本ある・
  存在しない出発点、といった人工の道路網でも想定どおりに動くことを確かめます。
- `test_efficiency.bat` … 候補を絞る高速化や重複の使い回しを入れた状態で、
  解が悪くならないこと・許した近傍の中では改善手が無いこと・乱数の使われ方が変わらないことを確かめます。
